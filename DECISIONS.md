# Решения по неоднозначностям ТЗ

Документ фиксирует выбор в спорных местах, чтобы не останавливаться на уточнениях. Дополняется по ходу разработки.

## Пивот со старого scaffold

В репозитории на момент старта лежал каркас другого проекта — лендинг с админкой на пароле, Supabase и Resend (`middleware.ts`, `.env.example` с ключами Supabase/Resend, `package.json` с `@supabase/supabase-js`/`resend`). Он не имеет отношения к платформе организаторов из ТЗ (Next.js + Prisma/PostgreSQL + Telegram Login + grammY + node-cron). Каркас заменён полностью. Ветвевые файлы с брендингом (`Губкин Design System.docx`, логотип, фото) сохранены и перенесены в `brand/` — они не мешают и могут пригодиться для визуального стиля.

## Прочее

- **Аутентификация без Edge middleware.** Проверка Telegram Login Widget использует `node:crypto` (HMAC-SHA256), который недоступен в Edge Runtime. Поэтому проверка прав вынесена в серверные компоненты/server actions (`lib/auth.ts`), а не в `middleware.ts`. Это проще и не требует Edge-совместимых JWT-библиотек.
- **Сессия.** Простой подписанный cookie (HMAC над JSON-пейлоадом `{userId, exp}`), без внешних auth-фреймворков — их функциональность избыточна для одного способа входа.
- **Хранение времени.** Все `DateTime` в Postgres — `timestamptz` (UTC), Prisma это делает по умолчанию для `DateTime`. Форматирование в МСК — на уровне отображения (`lib/time.ts`, `Intl.DateTimeFormat` с `timeZone: 'Europe/Moscow'`).
- **`targetDate`/день мероприятия.** Хранится как `DateTime` (полночь UTC даты), фактическое время — в свободном поле `timeSlot`. Задачи группы `EVENT_DAY` получают `dueDate = targetDate` (сравнение по дате, не по времени).
- **Автоназначение при отсутствии человека в отделе.** Задача создаётся с `assigneeId = null`, в интерфейсе подсвечивается как «без исполнителя» (класс/бейдж), это и есть требуемая подсветка — отдельного поля не заводим.
- **Триггер `SECURITY_SUBMITTED`.** Добавлен в enum `EventTrigger` вместе с `DATE_FIXED`, `SECURITY_ANSWERED`, `REGISTRATION_CLOSED`, `EVENT_DONE`, как указано в разделе 7.
- **Тесты.** Vitest, без БД — тестируется чистая логика генерации дат/исполнителей и функции проверки условий перехода стадий (принимают на вход простые объекты, не Prisma-клиент), чтобы не требовать поднятой Postgres в CI.
- **Cron.** `node-cron` внутри Next.js процесса, запуск планировщика через `instrumentation.ts` (официальный хук Next.js для кода, который должен выполниться один раз при старте сервера), с флагом в module-scope против повторной регистрации при hot-reload.
- **Бот и веб — один процесс.** grammY-бот запускается тем же `instrumentation.ts` через long polling; вебхук не настраиваем, чтобы не требовать публичного HTTPS для дев-окружения.
- **Идеи и авторство.** Для анонимной идеи `authorId` не просто `null`, а действительно не передаётся в `create()` — Prisma подставит `null` как дефолт колонки, поле никогда не заполняется значением текущего пользователя, даже если он вошёл.
- **Разрешение календаря/списка/доски** — общий клиентский компонент `EventsExplorer`, переключающий вид без перезапроса данных (данные грузит серверный компонент один раз).
- **Markdown.** Рендерится библиотекой `marked` (маленькая, без рантайм-зависимостей). Контент markdown (регламенты, описание мероприятия) редактируют только LEAD/ADMIN — это доверенные внутренние пользователи, поэтому HTML не прогоняется через дополнительный санитайзер (как и в обычных wiki-инструментах для закрытой команды).
